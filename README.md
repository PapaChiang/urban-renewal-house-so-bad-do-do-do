# 屋會壞 都都都

臺北市危老耐震風險地圖與政策行動排序工具，題目靈感源自[市政 debug 松](https://puma.taipei/hackathon)提案「危老耐震如何查，風險評級怎麼找」。本專案為概念驗證原型（PoC），目標為：

1. 幫助市府人員釐清地區風險排序
2. 減輕市府人員負擔，快速匯出報表，與相關單位啟動公辦都更、老屋健檢。

[線上原型連結](https://claude.ai/artifact/AaZJAvjnEe18dq3SjNHBgx)。

## 使用受眾

本專案供臺北市政府都市發展局、專業評估團隊及公民協作者使用。

## 功能範圍

系統以「風險排序 → 行動建議 → 調查交辦」為使用流程，以下為功能規格：

- **分析單位：** 以行政里為最小圖資單位，涵蓋臺北市 456 個里。
- **條件篩選：** 依建議行動篩選候選地區，並支援行政區、里名、風險、可行性與加查項目篩選。
- **指標排序：** 支援風險、可行性、土壤液化與人口高齡化等指標的個別排序。
- **檢視模式：** 清單呈現各里指標及建議行動；地圖呈現空間分布，供辨識鄰近區域及整合資源。
- **交辦清單：** 以里為單位匯出 CSV 檔案，包含行動建議及加查項目。
- **模型設定：** 透過設定檔調整風險公式參數，預設公式如下。

### 風險排序

風險分數整合危害、建物脆弱度、人口暴露及搶救困難指標，用於比較各里的調查優先程度。以下列出原型公式、指標定義與主要計算假設。

```text
風險分數 = H^0.485 × V^0.349 × E^0.166 × (1 + 0.35 × R)

H：危害，土壤液化潛勢
V：脆弱度，建物屋齡與構造（模擬值）
E：暴露，高齡人口人數、比例與人口密度
R：搶救困難，消防搶救相關清冊
```

- V 的屋齡與構造權重為 70% 與 30%；E 的高齡人口人數、比例與人口密度權重為 40%、40% 與 20%。各分項先標準化，再轉換至 0.1–1，避免零值使乘積歸零。
- H、V、E 經極端值處理與尺度轉換後，使用 AHP 假設比較矩陣及熵權法組合權重。AHP 尚未經專家問卷驗證，消防加成係數 `0.35` 亦為假設。
- 高液化潛勢面積占比至少 50%，且 1974 年前建物占比至少 30% 時，列為極高風險。

### 可行性排序

可行性分數用於比較地區的更新推動條件，並與風險分數共同決定行動分類。原型以街廓完整度、公有地比例、產權複雜度、巷寬及高齡比例加權，按全市中位數區分高低。

### 行動建議

依風險與推動可行性轉換為四類行動建議，對應如下：

| 風險 | 推動可行性 | 原型分類               | 後續作業                           |
| ---- | ---------- | ---------------------- | ---------------------------------- |
| 高   | 高         | 公辦都更               | 查核基地、產權、居民意願及實施條件 |
| 高   | 低         | 結構補強／危老重建輔導 | 安排專業評估，盤點補強與輔導條件   |
| 低   | 高         | 民間自辦都更           | 提供更新諮詢，確認社區需求         |
| 低   | 低         | 一般追蹤               | 更新資料並重新評估                 |

上述資料不足以完整重建原型。正式運作仍需補齊行政里界、逐棟屋齡與構造、基地及產權等資料；建物脆弱度與多數可行性輸入目前仍為模擬值。資料匯入須保留來源、版本、下載日期、授權與處理紀錄。

## 市府上任 100 天內的落地方案

本方案以系統試辦及啟用高優先序地區行動為階段目標：

- 上任後第 50 天：建置可供承辦人使用的初篩與交辦試辦系統，以全市公開圖資為底圖，選定數個里區作為優先行動案例。
- 上任後第 100 天：啟動 10 個高優先序里區的後續行動。

以下為建議分工及所需資料：

| 建議單位                                                                                      | 工作與所需資料                                                                             |
| --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 都市發展局（統籌）／[都市更新處更新開發科](https://uro.gov.taipei/cp.aspx?n=2EBB1B0792C28813) | 確認試辦範圍、交辦規格及公辦都更前期評估流程；提供候選基地、既有案件與調查資料。           |
| [建築管理工程處使用科](https://cmo.gov.taipei/cp.aspx?n=6D7C5E6952CD7035)                     | 檢視耐震指標及老屋健檢轉介流程；協調取得試辦區逐棟位置、屋齡、構造、建使照與既有評估紀錄。 |
| 工務局／消防局                                                                                | 分別核對液化圖資等級與版本、消防通道及搶救困難清冊；確認路段定位及現況。                   |
| 民政局／區公所                                                                                | 提供人口統計、行政里界及代碼對照，協調里辦公處與社區聯繫。                                 |
| 地政局／相關公有土地管理機關                                                                  | 協調取得地籍、建物及公有土地資料，支援基地範圍與產權條件查核。                             |
| 資訊局／主辦機關資訊單位                                                                      | 支援系統部署、資料交換、存取權限、資安檢查與維運交接。                                     |

## 專案限制

本專案尚有部分資料為推估值，若能補齊以下資料，將幫助專案判讀更將準確：

- 逐棟建物資料：建物位置、屋齡、構造、建使照及耐震評估紀錄，用於計算實際脆弱度與篩選健檢對象。
- 地籍與產權資料：候選基地範圍、地號、權利人數及持分、公有土地比例，用於確認更新範圍與產權整合條件。
- 街廓與道路現況資料：街廓邊界、實測巷寬、消防通道位置及障礙物，用於驗證街廓完整度與搶救可及性。

## 協作規範

本節規範問題回報、修改提交及資料公開方式，以維持變更的可追溯性與驗證依據。涉及模型調整或敏感資料時，應依下列要求提供說明並處理資料。

1. 透過 GitHub Issues 提出問題；資料問題請附來源、版本與影響範圍；操作問題請附重現步驟。
2. 以 Pull Request 提交修改，說明目的、驗證方式與影響。模型或門檻調整須附依據及調整前後比較。
3. 公開資料、Issue 與附件不得包含住戶個資、非公開聯絡方式或未去識別的調查紀錄。
